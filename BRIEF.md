## 1. Контекст і ціль

Зараз сайт — **візитка** з 4 секціями (About / Skills / Projects / Contact), темна тема, контент у `assets/i18n/*.json`. Продуктових CTA немає.

**Нова ціль:** перетворити сайт на **ультра-сучасний one-page landing**, який продає мене як інженера-підрядника для розробки, інтеграції AI та підтримки сервісів і застосунків. Сайт має:
- чітко формулювати послуги,
- показувати кейси з результатами,
- вести клієнта до дії через **форму «Start a project»**,
- виглядати преміально (референси: **clay.global**, **lazarev.agency**, з motion-акцентами в дусі **lusion.co**).

## 2. Технічні обмеження (НЕ міняти без обговорення)

- **Angular 18 standalone components** (міграція стека на Next/Vue виключена).
- **TypeScript 5.5, strict mode** — увімкнений, не послаблювати.
- **@ngx-translate/core** для i18n (EN / DE / UA) — зберегти, ключі паралельно у всіх трьох файлах.
- **Збереження деплою на Netlify** (SPA з `dist/`). У `.npmrc` лишається `legacy-peer-deps=true`; `overrides` у `package.json` не чіпати — вони потрібні для збірки Angular 18.
- **Builder**: класичний `@angular-devkit/build-angular:browser`. Бюджет: warn 2mb / error 5mb — стежити за розміром bundle.
- Продуктивність: ціль — близько 90+ у Lighthouse (Performance / Accessibility / SEO).
- Node-версія Netlify має підтримувати Angular 18.

### 2.1. Мова через URL-маршрут (прийнято)

Реалізувати **справжні URL-маршрути** замість клієнтського перемикача:
- `ihorshulha.dev/` → EN (за замовчуванням)
- `ihorshulha.dev/de` → DE
- `ihorshulha.dev/ua` → UA

Що для цього треба:
- Angular Router з параметром `:locale` (lazy-load контенту через `@ngx-translate` + зміна `translate.use(lang)` при зміні роута).
- Перехід між мовами = зміна URL, а не лише стану сервісу.
- **Netlify SPA redirects**: у `_redirects` або `netlify.toml` додати `/*  /index.html  200`, щоб усі `/de`, `/ua` віддавали Angular-додаток.
- `hreflang` у `index.html` стає валідним (вказує на реальні сторінки). Додати `canonical` URL.
- Запамʼятовування обраної мови через `localStorage`, але URL — джерело правди.

## 3. Стек анімацій (додати)

- **GSAP + ScrollTrigger** — основний motion-движок (скрол-анімації, reveal, паралакс).
- **Three.js (або легкий canvas/WebGL)** — лише для інтерактивного фону hero. Тримати мінімальним, щоб не порушити бюджет.
- Альтернатива, якщо Three.js перевищить бюджет: **canvas 2D / shader на чистому WebGL / CSS-only mesh-gradient** — на розсуд виконавця, але інтерактивний фон обовʼязковий.
- Анімації мають поважати `prefers-reduced-motion` (вимикатися для accessibility).
- Ліниве завантаження важких бібліотек (Three.js) через dynamic `import()` поза critical path.

## 4. Інформаційна архітектура (one-pager)

Один довгий скрол, секції як окремі standalone-компоненти. Порядок зверху вниз:

1. **Hero** — імʼя, позиціонування одним рядком, інтерактивний фон, два CTA.
2. **Services** — 4 картки послуг.
3. **Work / Case studies** — анонімні кейси з результатами.
4. **About** — коротко, з локацією.
5. **Process** (опційно) — як я працюю (3-4 кроки). Підсилює довіру.
6. **Contact / Start a project** — форма + прямі контакти.
7. **Footer** — Impressum, локація, мови.

Ст липкий nav (anchor-links до секцій) + перемикач мов. Мобільне меню-бургер.

**Головне твердження (hero):** інженер, що проєктує, будує та підтримує сервіси й застосунки — від бекенду до AI-фіч, від хмари до UI. Відкритий для співпраці та реалізації ідей.

**4 послуги (секція Services):**

| # | Послуга | Опис (коротко) | Стек |
|---|---------|----------------|------|
| 1 | **Backend Engineering** | Високонавантажені системи, мікросервіси, API, платіжні інтеграції | Java, Spring Boot, Kotlin, Go, Python |
| 2 | **AI Integration** | Підключення LLM, RAG, агентні схеми, AI-фічі в продукти | LLM APIs, RAG, vector DB, orchestration |

**AI** — не окремий spotlight, а **одна з 4 послуг** (картка нарівні з іншими), згадана також у навичках та кейсах.

## 6. Кейси (анонімно + результати)

Без назв компаній (NDA). Кожен кейс у форматі:
- **Що:** тип системи (напр. «Cloud Billing SaaS»).
- **Стек:** 3-5 технологій.
- **Моя роль:** коротко.
- **Результат:** конкретна метрика або ефект (продуктивність, охоплення, час релізу).

Переробити поточний список із `assets/i18n/*.json` (8 backend + 1 fullstack + 2 mobile) у 4-6 найсильніших кейсів з акцентом на **результат**, а не на список технологій. Mobile/Flutter кейси — тільки якщо посилюють історію.

### 6.1. Метрики кейсів (прийнято)

**Підхід:** виконавець пропонує конкретні цифри на основі описів кейсів, власник їх **підтверджує або виправляє**. Кожна сформульована метрика позначається `TODO: verify metric with owner` — без підтвердження в прод не йде.

Формат у коді:
```
Результат: → TODO: verify metric with owner
  "Processing 5k+ invoices/min, 99.95% uptime over 12 months"
```

Правила формулювання метрик:
- Базуватися на тому, що вже описано в `assets/i18n/*.json` (тип системи, стек, роль).
- Правдоподібний діапазон для нішевих domain (fintech/payments, realtime collaboration, healthcare, crypto).
- Не вигадувати екстремальні цифри — консервативний підхід.
- Альтернатива для чутливих кейсів — якісні формулювання («reduced release cycle», «high-availability in production») без жорстких чисел, якщо власник не затвердить метрику.

### 7.2. Загальне
- **Типографіка:** 1-2 сучасних шрифти з Google Fonts або Variable Font; великий, сміливий hero-заголовок; чітка ієрархія h1→h4.
- **Зображення:** нових фото поки нема → **абстрактні візуали** (gradient-mesh, canvas-арт, SVG-патерни), без портретів у hero.
- **Сітка/простір:** щедрі відступи, тонкі лінії-роздільники, картки з мʼяким gradient/glow на hover.
- **Motion (гібрид):**
  - Hero: інтерактивний фон + анімований вхід заголовка.
  - Між секціями: scroll-reveal, паралакс, плавні переходи.
  - Hover-мікроанімації на картках і CTA.
  - Не переробляти в повний motion-портфоліо — балансувати емоцію з конверсією.
